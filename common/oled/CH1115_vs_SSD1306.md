# CH1115 vs SSD1306 Comparison Guide

Detailed technical comparison between the CH1115 and SSD1306 OLED display controllers supported by this project.

---

## Quick Comparison Table

| Feature | CH1115 | SSD1306 |
|---------|--------|---------|
| **Resolution** | 128×64 pixels | 128×32 pixels |
| **Display Type** | Monochrome OLED | Monochrome OLED |
| **I2C Address** | 0x3C (or 0x3D) | 0x3C (or 0x3D) |
| **Device ID** | 0x15 | 0x15 |
| **Operating Voltage** | 3.3V - 5V | 3.3V - 5V |
| **Interface** | I2C (TWI) | I2C (TWI) |
| **Color Depth** | 1-bit (monochrome) | 1-bit (monochrome) |
| **Contrast Range** | 0x00 - 0xFF | 0x00 - 0xFF |
| **Class Name** | `CH1115Display` | `SSD1306Display` |
| **Library Support** | ✓ Full support | ✓ Full support |

## Protocol Differences

### I2C Command Framing

- Both displays use I2C with the same control bytes:
  - `0x00` for commands
  - `0x40` for data
- Both drivers use the same default addresses: `0x3C` or `0x3D`.

### Initialization Protocol

#### CH1115

- Reads status from the device and uses a simple startup flow.
- Turns the display on with `0xAF` and sets normal display mode with `0xA4`.
- Sets contrast directly with the command `0x81`.

#### SSD1306

- Uses a longer register setup sequence.
- Sends display off (`0xAE`) before configuring:
  - clock divider (`0xD5`)
  - multiplex ratio (`0xA8`)
  - display offset (`0xD3`)
  - start line (`0x40`)
  - charge pump (`0x8D`, `0x14`)
  - memory mode (`0x20`, `0x00`)
  - segment remap (`0xA1`) and COM scan direction (`0xC8`)
  - COM pins (`0xDA`)
  - contrast (`0x81`)
  - pre-charge (`0xD9`)
  - VCOM detect (`0xDB`)
  - resume RAM content (`0xA4`)
  - normal display (`0xA6`)
  - deactivate scroll (`0x2E`)
  - display on (`0xAF`)

### Scrolling Protocol

#### CH1115

- Uses `0x24` to set horizontal scroll range.
- Uses `0x26` / `0x27` for horizontal scroll setup.
- Offers scroll modes including continuous, single-screen, and one-column.
- Provides breathing effect control with `0x23`.

#### SSD1306

- Uses `0x26` / `0x27` for horizontal scroll.
- Uses `0xA3` to set vertical scroll area.
- Uses `0x2A` / `0x29` for vertical scroll and `0x2C` / `0x2D` for single-shot scroll.

### Addressing and Memory Mapping

- Both use page addressing for display updates.
- CH1115 and SSD1306 both separate command and data bytes in the same I2C stream.
- SSD1306 exposes explicit address setup commands for column and page, while CH1115 relies on its own page/column write flow.

### Practical Protocol Impact

- CH1115 is simpler to initialize and control at a high level.
- SSD1306 requires more setup commands but supports standard OLED register configuration and more flexible scrolling.

## Note about SH1107 support

A lightweight compatibility shim `SH1107Display.h` has been added to reuse the existing
`CH1115Display` implementation for SH1107-based modules. This provides a quick way to
use `SH1107Display` in projects while a dedicated SH1107 driver (tailored to its datasheet)
is developed. The shim maps the SH1107 symbol names to the CH1115 implementation; verify
behavior against a real SH1107 module and adjust initialization/command sequences as
specified in the SH1107 datasheet when fine-tuning is required.


## Hardware Differences

### Resolution & Physical Size

#### CH1115

- **Resolution:** 128×64 pixels (8192 total pixels)
- **Dimensions:** Typically 2.42" diagonal
- **Aspect Ratio:** 2:1 (wider than tall)
- **Pixel Size:** Larger individual pixels
- **Common Module Size:** 128×64mm PCB

#### SSD1306

- **Resolution:** 128×32 pixels (4096 total pixels)
- **Dimensions:** Typically 0.96" - 1.3" diagonal
- **Aspect Ratio:** 4:1 (much wider than tall)
- **Pixel Size:** Smaller individual pixels
- **Common Module Size:** 27×27mm or similar compact size

### Display Memory

#### CH1115

```
Total Pages: 8 pages
Bytes per page: 128 bytes (one row of pixels)
Total memory: 8 × 128 = 1024 bytes
Pixels per page: 128 × 8 = 1024 pixels
```

#### SSD1306

```
Total Pages: 4 pages
Bytes per page: 128 bytes (one row of pixels)
Total memory: 4 × 128 = 512 bytes
Pixels per page: 128 × 8 = 512 pixels
```

### Brightness & Contrast

Both support similar contrast ranges:

- **Range:** 0x00 to 0xFF
- **Default:** 0x80 (mid-range)
- **CH1115 specific:** Full range: 0x00 - 0xFF
- **SSD1306 specific:** Full range: 0x00 - 0xFF

## Software Differences

### 1. Special Features

#### CH1115 Unique Features

- **Breathing Effect** - Pulsing display brightness

  ```cpp
  ch1115.breathingEffect(1);  // Enable
  ch1115.breathingEffect(0);  // Disable
  ```

- **Advanced Scroll Modes** - Three scroll modes available
  - Continuous horizontal/vertical scroll
  - Single-screen scroll
  - One-column scroll mode

#### SSD1306 Unique Features

- **Single-Shot Scroll** - Scroll once then stop

  ```cpp
  ssd1306.scrollOnce(startPage, endPage, startCol, endCol, direction);
  ```

- **Vertical Scrolling** - In addition to horizontal

  ```cpp
  ssd1306.scroll(SSD1306_SCROLL_VERTICAL_LEFT);
  ssd1306.scroll(SSD1306_SCROLL_VERTICAL_RIGHT);
  ```

- **Page-Based Clear** - Dedicated clear function

  ```cpp
  ssd1306.clearPage(0);  // Clear page 0
  ```

### 2. Class API Differences

#### CH1115Display API

**Unique methods:**

```cpp
class CH1115Display {
  void breathingEffect(uint8_t on);  // NOT in SSD1306
  void drawString2(uint8_t x, uint8_t y, const char *pText);
  void drawInt(uint8_t x, uint8_t y, int32_t num);
  void startPageDrawing(uint8_t x, uint8_t y);  // Direct page drawing
  uint8_t updatePagePixel(uint8_t y, uint8_t colour);
  uint8_t updatePageColumn(uint8_t pattern, uint8_t mode, uint8_t mask);
  void endPageDrawing();
};
```

#### SSD1306Display API

**Unique methods:**

```cpp
class SSD1306Display {
  uint8_t scrollOnce(...);          // NOT in CH1115
  uint8_t drawInt(..., uint8_t base);  // With base parameter
  uint8_t drawChar(uint8_t x, uint8_t y, char c);  // Character-level drawing
  uint8_t drawPString(...);         // Program memory string
  uint8_t drawString2(...);         // Private in CH1115
  void clearPage(uint8_t p);        // Convenience clear
};
```

#### Shared Methods (Both Have)

```cpp
// Basic screen setup
void init(uint8_t contrast = 0x80);
void enable(uint8_t on);
void invert(uint8_t on);
void flip(uint8_t on);
void contrast(uint8_t contrast);

// Scrolling
void scrollArea(uint8_t startPage, uint8_t endPage, uint8_t startCol, uint8_t endCol, uint8_t dir, uint8_t nbFrame);
void scroll(uint8_t mode);

// Full screen
void drawScreen(uint8_t pattern, bool border = false);
void drawPage(uint8_t p, uint8_t pattern);
void drawPage(uint8_t p, uint8_t startcol, uint8_t nbcol, uint8_t pattern);

// Drawing
void drawString(uint8_t x, uint8_t y, const char *pText);
void drawPixel(uint8_t x, uint8_t y, uint8_t color);
void drawLine(uint8_t x0, uint8_t y0, uint8_t x1, uint8_t y1, uint8_t color);
void drawSprite(uint8_t x, uint8_t y, uint8_t w, uint8_t h, const uint8_t *data, uint8_t mode);
```

### 3. Initialization Differences

#### CH1115 Initialization

```cpp
CH1115Display display(128, 64);
display.init(0x80);  // Use default or custom contrast

// Simple initialization sequence:
// 1. Initialize I2C
// 2. Read device status (0x15)
// 3. Turn on display (0xAF command)
// 4. Set normal display mode (0xA4)
// 5. Set contrast
```

#### SSD1306 Initialization

```cpp
SSD1306Display display(128, 32);
display.init(0x80);  // Use default or custom contrast

// Complex initialization sequence:
// 1. Initialize I2C
// 2. Send display OFF command
// 3. Configure display clock divider
// 4. Set multiplex ratio
// 5. Set display offset
// 6. Set start line
// 7. Enable charge pump
// 8. Set memory addressing mode
// 9. Set segment remap
// 10. Set COM scan direction
// 11. Set COM pins
// 12. Set contrast
// 13. Set pre-charge period
// 14. Set VCOMH detect level
// 15. Turn display ON
```

### 4. Scroll Mode Constants

#### CH1115 Scroll Modes

```cpp
#define CH1115_SCROLL_6FRAMES 0x00
#define CH1115_SCROLL_32FRAMES 0x01
#define CH1115_SCROLL_64FRAMES 0x02
#define CH1115_SCROLL_128FRAMES 0x03
```

#### SSD1306 Scroll Modes

```cpp

#define SSD1306_SCROLL_128FRAMES 0x02
#define SSD1306_SCROLL_256FRAMES 0x03  // Supports 256 frames
```

### 5. Memory Mode & Addressing

#### CH1115

- Page addressing mode (default and only mode)
- Horizontal address counter automatically increments within pages
- Writing data automatically advances column position

#### SSD1306

- Multiple addressing modes available:
  - Page addressing (default, same as CH1115)
  - Horizontal addressing mode (automatically advances both column and page)
  - Vertical addressing mode
- Supports column and page address configuration

### 6. Internal Commands & Registers

#### CH1115 Commands (Selection)

```
0x2E - Scroll OFF
0x2F - Scroll ON
0x24 - Additional Horizontal Scroll Setup
0x26/0x27 - Horizontal Scroll Setup
0xAE - Display OFF
0xAF - Display ON
0xA4 - Normal display
0xA5 - Display all ON
0xA6 - Normal (non-inverted)
0xA7 - Inverted
0x81 - Set Contrast
```

#### SSD1306 Commands (Selection)

```
0x20 - Set Memory Mode
0x21 - Set Column Address
0x22 - Set Page Address
0x81 - Set Contrast Control
0x8D - Charge Pump Setting
0xA0/0xA1 - Segment Remap
0xA4 - Resume to RAM content
0xA5 - All pixels ON
0xA6 - Normal display
0xA7 - Inverted display
0xA8 - Set Multiplex Ratio
0xAE - Display OFF
0xAF - Display ON
0xC0/0xC8 - COM Output Scan Direction
0xD3 - Set Display Offset
0xD5 - Set Display Clock Divide Ratio
0xDA - Set COM Pins
0xDB - Set VCOMH Deselect Level
```

## Code Compatibility

### How to Switch Between Them

**Easy swap with preprocessor directives:**

```cpp
#define USE_CH1115  1
// #define USE_CH1115  0

#if USE_CH1115
  #include "CH1115Display.h"
  CH1115Display display(128, 64);
#else
  #include "SSD1306Display.h"
  SSD1306Display display(128, 32);
#endif

void setup() {
  display.init(0x80);
  display.drawString(0, 0, "Hello!");
}
```

### Features to Avoid for Portability

If you want code that works with both:

**❌ Don't use (CH1115 only):**

```cpp
display.breathingEffect(1);
```

**❌ Don't use (SSD1306 only):**

```cpp
display.scrollOnce(...);
display.drawPString(...);  // Use PROGMEM manually instead
```

**✅ Do use (both support):**

```cpp
display.drawString(...);
display.drawPixel(...);
display.scrollArea(...);
display.drawSprite(...);
```

## When to Use Which

### Use **CH1115** When You Need

- **Larger display** (128×64 vs 128×32)
- **More vertical space** for graphics or text
- **Breathing effect** animations
- **Detailed graphics** (more pixels)
- **Games/animations** that need height

**Typical Applications:**

- Game displays (Space Invaders)
- Complex graphics/charts
- Multi-line information displays
- Projects with ATmega chips (more resources)

### Use **SSD1306** When You Need

- **Compact size** (small footprint)
- **Lower cost** (widely available)
- **Minimal resources** (slightly more efficient)
- **Vertical scrolling** support
- **Character-level drawing** for text

**Typical Applications:**

- Arduino UNO projects (memory constrained)
- ATtiny projects (ultra-minimal)
- Status displays
- Serial monitors / debugging output
- Battery-powered devices

## Pin Connections (Both Identical)

```
Microcontroller    OLED Module
GND            →   GND
VCC (3.3/5V)   →   VCC
SDA (I2C)      →   SDA
SCL (I2C)      →   SCL
```

⚠️ **Note:** Both use same I2C pins, but **different I2C addresses** if you have multiple displays on same bus.

## Addressing Differences

### CH1115 Page Addressing

```
Page 0: Rows 0-7      (Y = 0-7)
Page 1: Rows 8-15     (Y = 8-15)
Page 2: Rows 16-23    (Y = 16-23)
Page 3: Rows 24-31    (Y = 24-31)
Page 4: Rows 32-39    (Y = 32-39)
Page 5: Rows 40-47    (Y = 40-47)
Page 6: Rows 48-55    (Y = 48-55)
Page 7: Rows 56-63    (Y = 56-63)

Total: 8 pages × 128 pixels = 1024 bytes
```

### SSD1306 Page Addressing

```
Page 0: Rows 0-7      (Y = 0-7)
Page 1: Rows 8-15     (Y = 8-15)
Page 2: Rows 16-23    (Y = 16-23)
Page 3: Rows 24-31    (Y = 24-31)

Total: 4 pages × 128 pixels = 512 bytes
```

Both support 256 brightness levels (0-255):

```cpp
// CH1115
ch1115.contrast(50);    // Dark
ch1115.contrast(128);   // Medium (default)
ch1115.contrast(255);   // Bright

// SSD1306
ssd1306.contrast(50);   // Dark
```

Both operate at similar brightness levels at same contrast values.

## Troubleshooting Differences

### If Initializing Fails

**CH1115:**

- May auto-enable display (0xAF command)
- Check if display is physically powered

**SSD1306:**

- Complex initialization sequence must succeed
- All steps must complete without I2C errors
- Charge pump must be enabled properly

### If Display is Blank

**CH1115:**

- Check breathing effect isn't enabled with low level
- Verify scroll mode is OFF (0xFF)

**SSD1306:**

- Verify display is enabled (0xAF sent)
- Check memory mode is correct (0x00 for page mode)
- Verify contrast is not 0x00
